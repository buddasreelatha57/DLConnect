# DL Connect

DL Connect is a mobile-first worker/employer marketplace. The React app runs as a website and as an Android app via Capacitor. A Java 21 / Spring Boot API stores accounts, job posts, and applications in PostgreSQL.

## What is included

- Worker and employer registration/sign-in with BCrypt password hashing and 12-hour signed access tokens.
- Job discovery, employer job posting, worker applications, and accept/decline decisions.
- Safety rules and a built-in work guidance helper.
- OpenStreetMap map tiles in a Three.js 3D view and a Leaflet 2D view, with device-location centering and job markers for posts that include coordinates.
- Android packaging with Capacitor and native location permission support. Android 8.0 (API 26) is the minimum, with target API 36 for current Play submissions.
- Database schema migrations managed by Flyway.

The original file, `index (1).html`, is retained as the prototype. The React project is in `client/`; the API is in `backend/`.

The new account flow uses a password because the prototype's on-screen OTP was demo-only. Phone numbers are validated but are not SMS-verified; connect an SMS OTP provider before relying on phone ownership. The UI currently ships in English. A production rollout also needs a published privacy policy, operational monitoring, real hosting, and a production map tile provider.

## Run locally

Requirements: Node.js 20.19+ (or 22.12+), Java 21, and Maven 3.9+. Docker Compose is optional if you want to run PostgreSQL locally.

1. In one terminal, change to `backend/` and run `mvn spring-boot:run -Dspring-boot.run.profiles=local`. The local profile uses a persistent H2 development database and does not need PostgreSQL or Docker.
2. In another terminal, change to `client/`, leave `VITE_API_URL` unset for local web development (Vite proxies `/api` requests to the API), and run `npm install` followed by `npm run dev`.
3. Open the Vite URL shown in the terminal. Register a worker and an employer with different phone numbers to try both roles. Keep both terminals running while using the app.

The local H2 database and local-profile JWT key are for development only. To use PostgreSQL locally, start it with `docker compose up -d database` and set `DATABASE_URL=jdbc:postgresql://localhost:5432/kaam_connect`, `DATABASE_USER=postgres`, and `DATABASE_PASSWORD=postgres` before starting the API. The default profile requires `JWT_SECRET` (at least 32 bytes), `DATABASE_URL`, `DATABASE_USER`, and `DATABASE_PASSWORD`; provide them as deployment secrets with strong values outside local development.

## Android build

Install Android Studio and its Android SDK, then from `client/`:

1. Set `VITE_API_URL` to the deployed HTTPS API URL before building the web assets. A phone cannot reach the developer machine via `localhost`.
2. Run `npm install` and `npm run android:sync` to copy the current web build into the checked-in Android project.
3. The generated project is configured for `minSdkVersion` 26 and target/compile API 36. Install Android SDK 36, verify the current Play Console requirement, then build/sign an Android App Bundle (`.aab`) using your own release key.

Publishing also requires a Play Console developer account, app listing, privacy policy, and a production-hosted API/database. Those credentials and services cannot be generated by this project. Google Play's [target API policy](https://support.google.com/googleplay/android-developer/answer/11926878) currently requires API 36 for new apps and updates from August 31, 2026; verify the policy again before release.

## Map and privacy notes

Location is requested only after the user taps the location control. It is used in the client to center the map; it is sent to the API only when an employer attaches coordinates to a job post. Jobs without coordinates remain visible in job lists but do not get map pins. The 3D scene uses OSM raster tiles and job/location markers; it does not claim to render 3D buildings or terrain. The 2D map remains available for accessibility and devices without WebGL.

OpenStreetMap data is made available under the ODbL. The public OSM tile service has a usage policy and is not a guaranteed production tile CDN. For a widely used production app, select a tile provider or host tiles that meets your traffic, attribution, and availability needs; configure the tile URL accordingly.

## API routes

- `POST /api/auth/register`, `POST /api/auth/login`
- `GET /api/users/me`
- `GET /api/jobs`, `GET /api/jobs/mine`, `POST /api/jobs`, `PATCH /api/jobs/{id}/close`
- `POST /api/applications`, `GET /api/applications/mine`, `GET /api/applications/for-employer`, `PATCH /api/applications/{id}`

Protected routes require `Authorization: Bearer <token>`. Configure `CORS_ALLOWED_ORIGINS` for the deployed web origin and the Capacitor origins that need access.
